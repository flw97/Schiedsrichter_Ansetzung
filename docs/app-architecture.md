# App architecture (port of the prototype)

Source of truth for the UI was `frontend/old/schiedsrichter-app-prototyp.html` (React, in-memory). Product rules and scope: [domain](./domain.md). Licence levels run from Grundlizenz to BWF-Accredited; leagues in code are Regionalliga Südost, 2. and 1. Bundesliga, with a BW focus.

## Backend (`backend/`)
- Auth: JWT access token plus refresh token (`POST /api/login`, username + password, demo password `demo1234`). The access token lasts 15 minutes (`AuthTokens`); `POST /api/refresh` rotates the refresh token (7 days) and returns a new pair. The SPA renews before expiry and on 401, and signs out when refresh is rejected. There is no idle logout. Password reset and deactivation call `User::revokeSessions` (bumps `token_version`, deletes refresh tokens), so outstanding access tokens stop working immediately. Logout revokes only the presented refresh token.
- Permissions: `app/Support/Permissions.php` (`MATRIX` -> gates of the same name, used as `can:<perm>` route middleware). Gate denials are logged via `Gate::after`.
- State: `StateController` returns everything the SPA needs in one JSON; the SPA reloads it after every action. Fine for club-sized data; switch to granular endpoints if it grows.
- Games (`games` table) cover manual events, imported NuLiga games and NuLiga games not yet taken over (`imported = false`). `nuliga_change` + `pending_*` hold pending NuLiga changes. Crew lives in pivot `game_referee` with `kind` confirmed | planned | head | planned_head and `reconfirmed`.
- `Game::confirm/plan/reopen` contain the assignment state transitions; leader = `Licenses::leader` (higher licence, then `season_count`).
- Actions return `{ pushes: string[] }` via `Controller::done()`; `App\Services\Push` is request-scoped. `GET /api/notifications?after={id}` returns the signed-in user's newer `push_messages` (at most 50). Rows stay unmailed (`emailed_at` null) until `GET` or `POST /api/cron` (`CRON_TOKEN` as `?token=` or header `X-Cron-Token`). `NotificationMailer` sends one mail per reachable account and then sets `emailed_at`. Accounts without an email, or inactive ones, are skipped and stay pending. The migration marks rows that already existed so the first run does not mail the old bell history.
- Password reset is immediate, not part of the cron: `POST /api/password/forgot` (`login` is username or email, always the same response) and `POST /api/password/reset`. The link targets `{FRONTEND_URL}/passwort-zuruecksetzen` and lives 60 minutes. A successful reset revokes that account's sessions (`User::revokeSessions`).
- NuLiga games come from the crawler at `https://nuliga.badminton-gomaringen.de/api` when `NULIGA_TOKEN` is set (`CrawlerNuLigaClient`: 1. Bundesliga, 2. Bundesliga, Regionalliga Südost). A side is `BW` when the club name is in `GET /api/clubs`. The crawler has no referee licences, so `licenses()` is empty and licences stay manual. Without a token, `NuLigaClient` still serves the demo schedule. The seeder always uses that demo client for tests and `migrate:fresh --seed`. Local Docker reads the token from `backend/.env.local`.
- A Schiedsrichter account creates an empty referee profile (`User::ensureReferee`). Any account edits its own name, username and email on one card and its password on another (`MeinBenutzerPage`, side by side once the page is at least 720px wide, `MeController::updateAccount`; the new password is confirmed in a second field and can be revealed), its licence (`MeineLizenzenPage`, same card layout, title Lizenz) and its address. The first licence or address save creates a referee profile when the account has none, so the person shows up in the left-hand overviews. Schiedsrichter still edit club, phone, availability and blackouts (`MeineDatenPage`). Admins still edit every licence and the Perspektiv-Team. Town lookup for the address is `domain/geo.ts`. Migration `2026_11_26_183400_drop_demo_fixtures` removes the seeded prototype referees, their logins, the demo schedule and “Hotel am Fluss” from databases that already had them. The staff logins `m.hartmann`, `s.weber` and `t.lang` stay.
- Referee statistics columns (`season_count`, `monthly_load`, `fairness`, `trend`, `last_game`) are seeded values, not yet derived from history.

## Frontend (`frontend/src/`)
- `stores/app.ts`: state + `act(method, path, body, successText)` (reloads state). Success and error toasts go through vue3-toastify (`notify.ts`). Toast surfaces, text, icons and the progress bar use the active Vuetify colors (`styles/main.css`, `--surface`, `--ink`, success/error/info/warning). While a session is open the store polls `GET /api/notifications?after=` every second, toasts new push messages, and prepends them to the bell. Access token, refresh token and expiry live in `sessionStorage` (`api.ts`). Requests renew the access token when it is inside the last minute or answered with 401. A rejected refresh clears the session and shows the toast „Deine Sitzung ist abgelaufen. Bitte erneut anmelden.“ A network failure during refresh does not. `App.vue` keeps the login form hidden while a stored token is restored via `GET /state`.
- `domain/`: pure logic ported from the prototype — `rules.ts` (mirror of `Licenses.php`), `dates.ts`, `geo.ts` (place table, distances), `planning.ts` (season planner heuristic), `ics.ts`; unit tests in `domain/__tests__` (`npm test`).
- `router/index.ts`: one route per page with `meta.perm`/`nav`; `App.vue` builds the drawer from it and redirects to the first allowed page. The drawer is the overview across people (Rollen, Lizenzen, Standorte). The app-bar user chip opens the own-account menu: Benutzer (`/mein-benutzer`), Lizenz (`/meine-lizenzen`), Standort (`/mein-standort`), Abmelden. Those three routes have no `nav`, so they stay out of the drawer, and no `perm`, so every signed-in role can open them. Abmelden lives only in that menu.
- Shared components: `GameSummary`, `GameFilter`, `ReportForm`/`ReportView`, `ConfirmAction`, `GeoMap` (Leaflet + OpenStreetMap tiles from `tile.openstreetmap.org`; OSM tile policy allows light use only, use an own tile server or provider for heavy traffic), `AddressPicker` (own Standort: address field and map stay in sync; `pickable` on `GeoMap`), `ScoreCompass`, `StatTile`, `ArchiveEdit`.
- Visual system: green/white theme in `plugins/vuetify.ts` (`light`: background `#F3F7F4`, primary `#1B4336`; `dark`: background `#0C1612`, primary `#8FCBB0`). Default follows the system preference (`theme.ts`, `localStorage` key `ansetzung-theme`: `system` | `light` | `dark`). The drawer uses theme color `brand` (`#1B4336`) in both schemes. CSS tokens in `styles/main.css` (`--ink`, `--paper`, `--line`, …) read the active Vuetify variables. `ThemeToggle.vue` sits in the app bar and on the login page. One typeface, Inter (`.font-display` and `.font-mono` are Inter, the latter with tabular figures). Club mark: `frontend/public/logo.svg` (copy of the repo-root `logo.svg`). `favicon.ico`, `favicon.png` and `apple-touch-icon.png` are rasterized from that file.

## Gotchas
- Apache strips `Authorization` unless `SetEnvIf` is configured (see `backend/Dockerfile`); after changing the Dockerfile run `docker compose up -d --build backend`.
- After adding Vuetify components, Vite re-optimizes deps once and reloads (504 "Outdated Optimize Dep" in the console is transient).
- Geo positions come from the town name in addresses (`GEO_PLACES`), unknown towns count as 20 km. A picked own Standort stores `lat`/`lon` (`PUT /me/standort`); `refGeo` prefers those over the town. Address search and reverse geocoding go through `GET /api/geo/search` and `/geo/reverse` (Nominatim, cached one day, Germany only for search). The Standorte layer Ansetzung is the current Ansetzung (`activeGames`): the hall name when it contains a town, otherwise the town in the home-club name (`venuesOf`). Mössingen is listed so it is not matched as Singen.
